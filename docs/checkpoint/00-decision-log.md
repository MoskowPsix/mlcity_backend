## 2026-09 / 2026-10 — продуктовая рамка (одобрено руководством)

| Решение | Почему |
|---|---|
| Новые дисциплины живут в **Вокруг**, мотокросс в **МотоТреке** не ломаем | Разные продукты и аккаунты; риск регрессии мото |
| Доступ организатора = флаг в **админке** («доступ Чекпоинт»), не общая Organization события | Organization в Вокруг уже есть у любого автора афиши |
| Соревнование = обычное **мероприятие** + чекбокс хронометража | Не плодить вторую сущность «Competition» вместо Event |
| Комиссия: Excel + ручной ввод; поля ФИО, ДР, город, **группа/класс**, номер, RFID | RFID можно пустым до старта |
| «Заявиться» — **после MVP** | Централизованный список достаточен для пилота |
| Шаблон «своя дисциплина» настраивается **только в Чекпоинте** (аккаунт + кэш) | Комиссия Вокруг = список, не правила фиксации |
| Несколько судей на пилоте = **один общий логин** | Проще; отдельные операторы позже |
| MVP обязательно включает **live + итоги на карточке события** | Главная ценность продукта |
| До оплаты публикация по **флагу админки**; оплата как PRO (pay-service) — этап после/к коммерческому запуску | Не блокировать пилот ожиданием биллинга |
| Без подписки/флага: локальный хронометраж можно, облачный эфир — нет | Не срывать старт офлайн |
| v1 трасса = **один створ** | Многоточечность позже |
| Этапы 1 и 2 параллелят **два разработчика** после заморозки контракта импорта | Стык по JSON/API |

## 2026-10-02 — группы и Excel (контракт v1.1)

| Решение | Почему |
|---|---|
| **Группы/классы** — отдельный список в комиссии события + `groups[]` в API | Организатор видит структуру; Чекпоинт фильтрует заезд по группе |
| Excel: **скачать бланк** → заполнить → загрузить; при совпадении заголовков без маппинга | Понятно клиенту; меньше ошибок |
| Чужой Excel → **сопоставление колонок** → превью → импорт | Гибкость без отказа от бланка |
| Новое **group_name** в Excel **создаёт группу** автоматически | Не заставлять заводить группы вручную до Excel |
| **start_number** уникален в рамках события | Два «№12» на старте недопустимы |
| Импорт в API только **автор** события с доступом Чекпоинт | Безопасность |
| Повторный импорт: **upsert** по `participant.id`; пропавших в API **не удалять** локально в Чекпоинте автоматически | Не сорвать заезд mid-race |
| `publish_allowed` на **user** (пилот) | Проще, чем per-event |
| Контракт импорта **v1.1** | groups + group_id |
| Повторная загрузка Excel с тем же `start_number` | **Обновляет** существующего участника события (один однозначный match) |
| При старте заезда участник без RFID | Предупреждение + подтверждение, не жёсткий блок |
| Типы MVP в шаблоне | `mass_start_time`, `qualification_best` |
| Задачи этапов 1–2 детализированы в `03-yougile-tasks-stage-1-2.md` | Карточки переносятся в YouGile без додумывания scope |

## 2026-10-06 — комиссия одного события по почте

| Решение | Почему |
|---|---|
| Владелец приглашает в комиссию **этого** события по почте. Блок со статусами «принял» / «не принял» и удалением видит только он | Несколько людей ведут стартовый список, карточка мероприятия остаётся у владельца |
| Аккаунт с этой почтой сразу «принял». Неизвестная почта «не принял» до регистрации с неё | Доступ появляется вместе с аккаунтом, а не по чужой ссылке |
| Член правит группы, участников, Excel и может слать результаты. Чекбокс, удаление события и новые приглашения — только владелец | Чужой старт открыт, чужая карточка нет |
| Члену не нужен флаг «Доступ Checkpoint». Флаг публикации для ingest нужен автору, члену — нет | Приглашённый ведёт чужое событие, не получает свой хронометраж |
| Отдельные логины судей в приложении Чекпоинт по-прежнему после MVP | Это комиссия Вокруг, не второй аккаунт на площадке |

## 2026-10-09 — UX выбора спортивной дисциплины

| Решение | Почему |
|---|---|
| `work-mode-modal` — **единственное** место выбора: Мотокросс + сохранённые дисциплины + «Добавить новую спортивную дисциплину» | Не путать выбор и редактирование |
| Заголовок модалки: «Выберите спортивную дисциплину»; подзаголовок про смену в настройках | Понятный язык для судьи |
| «Добавить новую…» / ✎ на плитке → `discipline-editor` (имя + типы MVP) | Создание/правка отдельно от выбора |
| Тап по плитке = выбрать; тап по ✎ = редактировать | Два жеста без сюрпризов |
| Settings: блок «Спортивная дисциплина» — одна кнопка текущей → снова модалка; **без** отдельного hub «Дисциплины» | Одно место смены режима |
| Cold start: модалка только если выбор ещё не сохранён | Не спрашивать дисциплину каждый запуск |

## 2026-10-09 — локальные итоги vs облако / share

| Решение | Почему |
|---|---|
| Экран **локальных итогов** finished custom heat — задача **E2-11**, дозакрытие этапа 2 | Метки уже в SQLite; без UI судья не видит протокол после финиша |
| Локальный просмотр и опциональный локальный PDF (**E2-11b**) **не** блокируются флагом publish / подпиской | Не срывать работу на площадке офлайн |
| Эфир, итоги на карточке Вокруг, «поделиться» ссылкой на событие — **этап 3** | Главная зрительская ценность MVP |
| До оплаты право облачной публикации = флаг админки (`checkpoint_publish_override` → `publish_allowed`) | pay-service ещё не подключён; пилот не ждёт биллинг |
| Без флага сервер отклоняет ingest; локальные итоги остаются | Freemium publish, не freemium timing |

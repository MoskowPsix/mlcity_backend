# Правила приёмки и Definition of Done

Приёмка продуктового сценария: **Lead**.  
Код-ревью PR: по договорённости команды (например, второй разработчик); Lead не обязан ревьюить каждую строку.

---

## 1. Когда задача считается «Готово»

Задача переводится в **Готово** только если:

1. Код в целевой ветке / на **тестовом стенде** (или собранном APK/web для Чекпоинта).
2. Выполнены **критерии готовности** из карточки YouGile.
3. Lead (или делегат) прошёл **сценарий приёмки** и перевёл задачу из «На проверке».
4. Нет блокеров для следующей задачи по цепочке (или блокеры явно описаны в комментарии).
5. Для задач Чекпоинта, затрагивающих общий код: отмечен чеклист **регрессии мотокросса** ([05-motocross-regression-checklist.md](./05-motocross-regression-checklist.md)) либо явно указано «не затрагивает мото».

«Работает на локальной машине» без стенда/сборки — **не готово**.

---

## 2. Колонка «На проверке»

Разработчик переводит задачу сюда, когда критерии выполнены, и в комментарии указывает:

- где смотреть (URL стенда / сборка / ветка);
- тестовый логин (если нужен);
- что проверить за 5–10 минут;
- известные ограничения.

Lead в тот же или следующий рабочий день: **принять** или **вернуть** со списком правок (отдельные мелкие задачи предпочтительнее устных «доделай»).

---

## 3. Сквозные сценарии (минимум)

### Сценарий S1 — Вокруг комиссия (закрывает этап 1)

1. Админ выдал тестовому user доступ Чекпоинт + publish.
2. User создал мероприятие, включил чекбокс.
3. В комиссии: вручную создана группа «М18»; участник добавлен в эту группу.
4. **Скачан бланк Excel**, заполнен (в т.ч. новая группа «Ж18» только из колонки `group_name`) → загрузка без маппинга (если заголовки бланка) → превью → импорт.
5. Дубликат **стартового номера** при загрузке/ручном вводе отклоняется с понятной ошибкой.
6. Файл с **чужими заголовками** импортируется через сопоставление колонок.
7. `GET competitions` и `GET competitions/{id}` отдают `groups[]`, `group_id`, `group_name` по контракту **v1.1**.
8. Export JSON скачивается и совпадает с контрактом.
9. Другой user с доступом **не** видит чужое событие в API импорта (403/404).

### Сценарий S2 — Чекпоинт без эфира (закрывает этап 2)

1. Вход «Своя дисциплина», логин Вокруг.
2. Импорт мока v1.1 (groups + participants), затем боевого API (когда есть) или export-файла офлайн.
3. Правка RFID участнику без метки.
4. Создание заезда: тип из шаблона + фильтр по группе; прогон фиксации **без сети** (оба типа: mass и qualification — хотя бы по одному прогону).
5. Мотокросс: [чеклист регрессии](./05-motocross-regression-checklist.md) пройден.

### Сценарий S3 — Эфир (этап 3, позже)

1. Старт заезда с publish_allowed.
2. На карточке события Вокруг виден live.
3. После финала — итоги на карточке.
4. Без publish_allowed — сервер отклоняет ingest.

---

## 4. Фокус приёмки

- Сценарий пользователя, а не только наличие кода.
- Соответствие **контракту** полей (имена, null, ошибки).
- Понятные ошибки 401/403/404 для судьи.
- Отсутствие лишнего scope.

---

## 5. Definition of Done для эпика (этапа)

Эпик закрывается, когда:

- все задачи эпика в «Готово» или осознанно перенесены;
- соответствующий сценарий S1/S2/S3 пройден на стенде;
- список багов пилота заведён в YouGile, критичные закрыты.

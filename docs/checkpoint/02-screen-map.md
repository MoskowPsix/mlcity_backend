## A. Вокруг (этап 1)

### A1. Админка (Moonshine)

| Экран | Кто | Действия |
|---|---|---|
| Пользователь / доступ Чекпоинт | Менеджер | Включить/выключить **доступ Чекпоинт** |
| Тот же или рядом | Менеджер | Флаг **разрешить публикацию** (пилот до оплаты) |

### A2. Создание / редактирование мероприятия

- Как сейчас + чекбокс **«Использовать хронометраж Чекпоинт»**.
- Чекбокс виден **только** при доступе Чекпоинт.
- При включении: после сохранения — кнопки/ссылки **«Комиссия»** (и позже «Заявиться» — не в MVP).

### A3. Комиссия (своё событие с чекбоксом)

**Блок «Группы / классы»**

1. Таблица или список групп (название, число участников).
2. «Добавить группу», переименовать, удалить (если в группе 0 участников).

**Участники**

3. Таблица участников (ФИО, группа, номер, RFID, …).
4. **«Скачать бланк Excel»** — файл с фиксированными заголовками и 1–2 примерами (см. контракт §4.1).
5. **«Загрузить Excel»**:
   - заголовки как в бланке → сразу **превью** → подтверждение импорта;
   - иначе → **сопоставление колонок** → превью → импорт;
   - новые `group_name` из файла создают группы автоматически.
6. «Добавить участника» / редактирование / удаление.
7. Поля строки: фамилия, имя, отчество (опц.), дата рождения, город, **группа (выбор из списка)**, номер, RFID (опц.).
8. Ошибка при дубликате **стартового номера** в этом событии.

### A4. Профиль → Чекпоинт (заглушка MVP)

- Пока: статус доступа, список своих соревнований с хронометражем, статус «публикация разрешена/нет».
- Оплата — этап 5 (не рисовать checkout в MVP, достаточно заглушки).

### A5. Карточка события для зрителя (этап 3)

- Блок/вкладка **«Хронометраж»**: пусто → live → итоги.
- Не делать в этапе 1; заложить место в навигации карточки по желанию.

```text
Вокруг MVP (этап 1)
[Админка: доступ + publish flag]
        |
[Создать событие] --чекбокс--> [Комиссия: группы + участники]
                                  |
                    бланк Excel / загрузка / ручной ввод
        |
[Профиль → Чекпоинт: статус]
```

## B. Чекпоинт (этап 2)

### B0. Выбор дисциплины (корень нового UX)

- **Мотокросс** → текущий поток без изменений.
- **Своя дисциплина** → новый поток ниже.

### B1. Своя дисциплина — список шаблонов

- Список сохранённых шаблонов (имя).
- «Создать дисциплину».

### B2. Редактор дисциплины

- Имя.
- Список типов заездов (минимум для MVP: например «массовый старт по времени», «квалификация / лучшее время» — точные поднастройки уточняются в задачах B, не блокируют импорт).
- Сохранить в аккаунт (+ локальный кэш).

### B3. Логин Вокруг

- Экран/вкладка входа аккаунтом Вокруг (отдельно от МотоТрека).
- Ошибка, если нет доступа Чекпоинт.

### B4. Импорт соревнования

- Список с API (или файл офлайн-пакета).
- Подтверждение импорта → локальная копия события + участников.

### B5. Участники импортированного события

- Таблица: ФИО, номер, группа, RFID.
- Редактирование RFID.
- Предупреждение, если RFID пустой.

### B6. Создание заезда

- Выбор типа из шаблона дисциплины.
- Выбор участников (все / группа / вручную — минимум: все или фильтр по группе).
- Старт.

### B7. Хронометраж (один створ)

- Как привычный экран фиксации; правила — по выбранному типу.
- Локальные результаты без сети.

### B8. Эфир (этап 3, не этап 2)

- Кнопка «В эфир» / авто при старте — только когда появится контракт трансляции.
- В этапе 2 достаточно локального финиша.

```text
Чекпоинт MVP (этап 2)
[Мотокросс | Своя дисциплина]
              |
    [Шаблоны дисциплин] --> [Редактор]
              |
    [Логин Вокруг] --> [Импорт] --> [Метки] --> [Заезд] --> [Хронометраж]
```

## C. Сквозной сценарий приёмки (до эфира)

1. Админ выдал доступ тестовому пользователю.
2. Пользователь создал событие, включил чекбокс, заполнил комиссию (Excel + одна ручная строка).
3. В Чекпоинте: своя дисциплина → импорт → правка RFID → заезд → локальный результат.
4. Мотокросс-путь по-прежнему открывается и не падает на дымовом сценарии.

Эфир на карточке — сценарий этапа 3.
